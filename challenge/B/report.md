# 도전 B. 퍽 할당 알고리즘 비교

- 날짜: 2026-11-09 · 환경: Python 3.12.3 · x86_64
- 사례: `cases_b.yaml` 6 건 (유효 4 · 불가능 2). 불가능 사례는 소프트웨어 오류 시험용 (공식 출제 아님)
- 입력 순서: 퍽 ID 0 ~ 11 (박스 = id // 2 + 1, 짝수 X − 40 · 홀수 X + 40). ID 와 색은 고정 대응 아님
- 정렬 규칙: P2-01 · P2-03 오름차순, P2-02 · P2-04 내림차순, 동률이면 R → Y → G
- 실행 시간: 사례마다 200 번 돌린 평균 (ms)

## 방식

| 방식 | 코드 | 내용 |
|---|---|---|
| 순차 선택 (기본) | `mission_planner/allocation.py` `allocate_greedy` | R 은 빨강을, G 는 초록을 ID 순으로 먼저 가져가고 남은 것을 Y 로. 남은 것이 섞이면 실패 |
| 탐색 (개선) | `mission_planner/allocation.py` `y_options` + `enumerate_allocations` | Y 에 들어갈 빨강 수 = 빨강 − R, 초록 수 = 초록 − G 로 정해짐 → Y 모양 (2 가지) 마다 같은 색 · 모양 안에서 ID 조합 전부 나열. 불가능이면 먼저 명시적 오류 |

## 순차 선택: 사례별 성공 · 실패 이유

- V1_Q1_오름차순: **실패** — 순차 선택 실패: 남은 Y 후보 모양 ['box', 'cylinder']. 탐색 방식은 Y 모양을 먼저 정해 같은 퍽으로 성공
- V2_동률_내림차순: **실패** — 순차 선택 실패: 남은 Y 후보 모양 ['box', 'cylinder']. 탐색 방식은 Y 모양을 먼저 정해 같은 퍽으로 성공
- V3_한모양_부족_순차실패: **실패** — 순차 선택 실패: 남은 Y 후보 모양 ['box', 'cylinder']. 탐색 방식은 Y 모양을 먼저 정해 같은 퍽으로 성공
- V4_내림차순_Y6: R · G 를 ID 순으로 가져간 뒤 남은 Y 후보 [3(rb), 4(rb), 5(rb), 9(gb), 10(gb), 11(gb)] 가 모두 box

## 결론

- 탐색 방식: 유효 4 건 모두 12 개를 중복 · 누락 없이 할당, 불가능 2 건은 할당 전에 y_options 에서 원인을 밝힌 명시적 오류 (안전 정지).
- 순차 선택: 유효 사례 3 건 실패 (V1_Q1_오름차순, V2_동률_내림차순, V3_한모양_부족_순차실패). R · G 가 ID 순으로 먼저 가져가면서 Y 에 필요한 모양을 써 버려 남은 후보 모양이 섞임.
- 순차 선택도 불가능 2 건에서 오류를 내지만, 할당 가능 여부를 먼저 따지지 않아 "불가능한 문제" 와 "순서 때문에 실패" 를 구별하지 못한다 (V1 · X2 의 실패 원인 문구가 같음).
- 12 개라 탐색 비용은 작다 (조합 수 = 같은 색 · 모양 안 선택뿐). 경기 계획기는 이 나열에서 경로 비용 최소를 고른다 (`planner.plan`).
